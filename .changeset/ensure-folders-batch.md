Folders: `DbSet.ensureFoldersAsync(paths)` creates many folders and returns one result per path, in input order, so one bad path never costs the others theirs (#118). With `@speel/pnpjs`, folders at the same depth go out together in one `$batch` (chunked at 100), so round trips scale with folder depth, not folder count. A failure is reported per path: `invalidPath`, `requestFailed` (with the HTTP `status`), `parentFailed` (an ancestor failed; `cause` is its error) or `noResult`. Folders created before a failure stay; re-running the call is the recovery. New standard outcome type: `Result<T>` (`{ ok, value?, errors? }`, with `ok` deciding which is present), `IError` (`code`, `message`, `target`, `status`, `cause`), the `Result.ok` / `Result.fail` / `Result.unwrap` helpers, and `OperationFailedException` for turning a failed result into a throw. Breaking for custom providers: `IFileSystem.ensureFoldersAsync` now returns `ReadonlyMap<string, Result<string>>` and reports a path's failure in its result instead of throwing (`FolderErrorCode` names the codes). `ensureFolderAsync` now throws `OperationFailedException` when the server refuses the folder, instead of the provider's raw error, and `add({ folder })` reports every folder that could not be ensured in one `DbUpdateException` whose `innerErrors` are `IError`s.
